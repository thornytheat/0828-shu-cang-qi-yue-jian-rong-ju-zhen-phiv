# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。到交账时间仍有冲突记录、但每行都已有着落（账平）时，可填写意见后交账，冲突记录保留隔离，不会被提前算作采信。
5. 交账后在「交账后补证」面板处理冲突记录：
   - 只否认一份定义时选择 DENY，记录仍计隔离，批次结论不变。
   - 晚到补证给出正确字段定义时选择 CORRECT，记录恢复采信，受影响业务组自动重算；重算后全部组通过即可放行。
   - 已采信补证可撤回，记录退回隔离、受影响组失去通过资格，其他组照旧；撤回后允许重新补证。
6. 原批次证据始终可查；补证后的重算结果通过补证证据单独导出，一并保存于交接记录。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次与原始来源。恢复时使用原 Docker Compose 数据卷。
